# Plan: #7 Provider contract & sync orchestration, then #8 Service lifecycle & freshness

## Ground truth (already in repo)

`docs/architecture.md` is the design authority: it fixes the adapter contract (`validateCredentials()`, `capabilities()`, `fetchInventory(SyncContext)`, `fetchCostFacts(SyncContext, InventoryBatch)`), the 9-step sync algorithm, retry/redaction rules, and lifecycle semantics. The #3 schema is merged: `sync_runs` (status CHECK `queued|running|succeeded|partial|failed|cancelled`), `services` (identity `(provider_account_id, external_id)`, `first_seen_at`, `last_seen_at`, `missing_complete_runs`, `lifecycle_state`), `provider_capability_states`, `provider_credentials` (encrypted payload). Models + factories exist. `CostProjector` (#5) already derives cost staleness from `observed_at` + `config('costs.freshness_days')` — sync must not re-implement that.

Delivery: **two sequential PRs** — `feat/sync-orchestration` (#7), then `feat/service-lifecycle` branched off it (#8). No UI, no OVH adapter (those are #10–#12), no scheduling (deferred to #14 per decision), no new composer dependencies.

## Stage 1 — #7 `feat/sync-orchestration`

### 1. Provider contract + DTOs (`app/Domain/Providers/...`)
- `Contracts/ProviderAdapter.php` — interface with exactly the four doc'd methods; adapters return DTOs only, never persist Eloquent.
- `AdapterRegistry.php` — `register(string $providerKey, ProviderAdapter $adapter)` / `for(string $providerKey)`; registered as singleton in `AppServiceProvider` (empty until OVH lands); unknown key → `Exceptions/UnsupportedProviderException`.
- `Enums/BatchCompleteness.php` — `Complete | Partial | Unsupported | Failed` (string-backed; mirrors integrations.md "capability completeness").
- Exceptions: `ProviderException` (base), `TransientProviderException` (429/5xx/timeout — retryable), `InvalidCredentialsException` (never retried), `UnsupportedProviderException`, plus `InvalidBatchException` for invariant violations.
- DTOs under `Dtos/` (all `final readonly`): `SyncContext` (account, decrypted credential payload array — in-memory only, `now`), `CredentialCheck` (valid, fingerprint, warning?), `CapabilitySet` (supported keys: `inventory`, `subscriptions`, `renewal_quotes`, `usage`, `invoices`), `InventoryBatch` + `InventoryItem` (externalId, canonical category, name, providerType?, url?), `CostFactBatch` + `CostFact` (serviceExternalId, SourceKind, ChargeKind, Period, ?Money, EvidenceState, TaxBasis, validFrom, sourceRef, renewsAt?, autoRenew?). Every batch carries `completeness`, `observedAt`, `warnings[]`, `sourceRef`.

### 2. Sync orchestration (`app/Domain/Sync/...`)
- `Retry/RetryPolicy.php` — bounded attempts (config: `max_attempts=4`, base 500ms, cap 15s), exponential backoff with jitter via `Sleep::fake()`-able `Sleep` facade; retries **only** `TransientProviderException`; `InvalidCredentialsException` and batch-validation failures propagate immediately.
- `SyncOrchestrator.php` — the 9-step algorithm: acquire per-account cache lock (`sync:account:{id}:full`, TTL from config, non-blocking) → reconcile orphaned `queued|running` runs older than lock TTL (mark failed, summary "abandoned") → claim the queued `SyncRun` (conditional `queued→running` update; 0 rows ⇒ exit) → validate credentials only when `verified_at` is null (success sets `verified_at` + `fingerprint`; invalid ⇒ run `failed`, no retry) → `capabilities()` → fetch inventory/cost-facts **outside** any DB transaction, cost facts gated on `CapabilitySet` (`Unsupported` ⇒ phase skipped, not failed) → validate batch invariants (canonical category, known ⇒ amount+currency present, no duplicate external ids) → persist in one short transaction → finish run: `succeeded`/`partial`/`failed`, per-phase `counts`, sanitized `summary` warnings; update account `last_attempt_at`/`last_success_at` and upsert `provider_capability_states` (supported/healthy/last_attempt/last_success/last_observed). Lifecycle transitions are **not** in this stage (step 7 lands in #8).
- `Persistence/PersistInventoryBatch.php` — idempotent upsert of services by `(provider_account_id, external_id)`; update descriptive fields when changed; set `first_seen_at`/`last_seen_at` **on create only** (ongoing seen/missing transitions are #8).
- `Persistence/PersistCostFacts.php` — idempotent by `identity_key`, scheme mirroring manual slice: `logical_charge_key = {provider_key}:charge:{sourceRef}`, `identity_key = {logical}:from:{Y-m-d}` (+ `:vN` on same-day collision, like `UpdateManualCost`). Price-affecting change (amount/currency/period) ⇒ close open version and open a new one under the same logical key, re-attaching coverage; same data ⇒ update `observed_at`/`evidence_state`/renewal in place; never touches `is_manual_override` rows. Coverage pivots attached idempotently; renewals upserted on the newest version.
- `Actions/RequestSync.php` — the single entry point ("sync now" = same path): refuses when an active run exists, creates the `queued` run, dispatches the job.
- `Jobs/SyncProviderAccount.php` (`ShouldQueue`, database queue, `tries=1` — expected failures are recorded on the run, not rethrown; `failed()` hook marks the run failed on unexpected crashes).
- `Commands/SyncNowCommand.php` — `lafiel:sync {--account=*} {--trigger=manual}`; loops enabled accounts through `RequestSync`, reporting refused accounts; registered via `->withCommands()` in `bootstrap/app.php`.
- **Migration**: partial unique index on `sync_runs (provider_account_id) WHERE status IN ('queued','running')` — the DB owns "one sync per account", same philosophy as service identity.

### 3. Support + config
- `app/Domain/Support/Redaction/Redactor.php` — value-based scrubbing: collects secret values from the credential payload and strips them from warning strings/arrays before anything reaches `SyncRun.summary` or logs.
- `config/sync.php` — retry bounds, lock TTL, orphan threshold (lifecycle threshold key added in #8).
- Health: `/up` already checks app+DB only (`VerifyDatabaseHealth`); add a regression test proving no adapter is resolved during a health request.

### 4. Tests (#7)
- Unit: `RetryPolicy` (backoff sequence/bounds, jitter range, no retry on invalid credentials, recovery on transient), `Redactor` (secret never appears in output even when embedded in a warning).
- Feature (`tests/Feature/Domain/Sync/SyncOrchestrationTest.php`, fake adapter bound into the registry — doubles as the template for the OVH adapter): complete happy path (services, cost items, coverage, renewals, capability rows, run `succeeded` with counts); idempotent re-sync (second run creates no duplicates, bumps `observed_at`); price change supersedes (new version, old closed, renewal follows); partial batch persists data, run `partial`, **no** missing/counter changes; transient exhaustion ⇒ run `failed`, last good data intact, nothing zeroed; invalid credentials ⇒ fail fast (assert attempt count = 1); disabled account skipped; unknown provider key ⇒ sanitized failure; parallel-run dedupe (`RequestSync` refuses while active; unique index rejects the race; lock held ⇒ second job exits); orphaned run reconciliation; secrets absent from `summary` and log fake.

**Done when**: `vendor/bin/pint --dirty`, `vendor/bin/pest` on the new files, and full `composer test` (pint + phpstan L7 + pest) all green.

## Stage 2 — #8 `feat/service-lifecycle` (branched off Stage 1)

### 1. Config
`config/sync.php`: `'inactive_after_complete_runs' => env('LAFIEL_INACTIVE_AFTER_COMPLETE_RUNS', 3)`; document the var in `.env.example`.

### 2. Lifecycle engine (`app/Domain/Inventory/Lifecycle/ApplyInventoryLifecycle.php`)
Applied by the orchestrator after persistence, driven by batch outcome:
- **Complete success**: present services → `last_seen_at = now`, `missing_complete_runs = 0`, `active` (also reactivating from `missing`/`inactive`); absent provider-discovered services → counter++ ⇒ `missing`, and at threshold ⇒ `inactive`. Never hard-delete.
- **Partial success**: observed services refresh `last_seen_at` and return to `active` (presence resets the counter — absence in a partial run changes **nothing**).
- **Failed**: no service row is touched at all.
- Manual services (`provider_account_id IS NULL`) are never touched.
- Capability staleness: failed/partial runs mark **touched** capabilities `healthy = false` while preserving last-good timestamps; success sets `healthy = true` and advances `last_success_at`/`last_observed_at`.

### 3. Cost-fact ending on complete absence (per your decision)
New `Persistence/EndAbsentCostFacts.php`: when the cost-facts phase completed **fully**, open provider-sourced facts of that account whose logical charge is absent from the batch get `valid_to = observedAt − 1 day endOfDay` (same convention as `EndManualCost`). Partial or failed runs never end anything, never write zero, never treat absence as cancellation. Renewals on ended facts stay untouched (historical evidence).

### 4. Projection independence
Sync/lifecycle never mutates cost amounts or the projector: an inactive service's existing costs keep projecting (flagged stale by `freshness_days`, not hidden) — "fresh inventory must not hide old costs".

### 5. Tests (#8) — `tests/Feature/Domain/Inventory/ServiceLifecycleTest.php` + sync-test additions
Threshold via config override (2): absent in N consecutive **complete** runs ⇒ missing → inactive; partial/failed never advance the counter or mark missing; presence (even partial) resets counter and restores active; return in complete inventory reactivates; manual services untouched; complete-batch absence ends the charge at the observation date while partial/failed absence doesn't; unknown amounts stay unknown (no zero written); capability stale-marking preserves last-good timestamps; projector output for old costs unchanged after a fresh sync.

**Done when**: same quality bar as Stage 1, then full `composer test`.
